## A workbench for staying with the writing

ZenTex began when my Politecnico di Milano–linked Overleaf subscription expired. I wanted to keep manuscripts on my own computer without losing the closeness between writing and seeing a document take shape.

Years of writing with LaTeX had left a collection of small interruptions: moving between source and output, finding a section across files, looking up citation keys, and keeping revision notes somewhere useful. My question was: **how could the workbench carry more of that coordination, so I could stay with the argument?**

Using <a href="https://www.texifier.com/" target="_blank" rel="noopener noreferrer">Texifier</a> as a behavioural reference, I worked with Workbuddy and REA to develop an independent macOS application. The project has grown around three decisions: keep one editable text, treat the project as a connected whole, and make uncertain or destructive actions explicit.

## One text, two ways to read it

Preview is a layer on the source. Headings gain hierarchy, equations render through KaTeX, and figures, tables, and lists become readable in place. Moving the cursor into a decorated passage reveals its LaTeX for direct editing. There is no second editable document to synchronise.

<LightboxImage src="/assets/projects/zentex/source-20261027.png" alt="ZenTex source view with LaTeX commands and manuscript text" caption="Source mode keeps the document directly accessible." />
<LightboxImage src="/assets/projects/zentex/preview-20261027.png" alt="ZenTex preview mode showing readable headings and an inline figure in the manuscript" caption="The same text becomes readable in place; entering a passage reveals its source." />

**Read → place the cursor → edit → return to the text.** This does not replace the final typeset page. It lets the writer inspect a sentence or equation before returning to the PDF for layout decisions.

### Make room for the current thought

In Zen mode, only the passage at the cursor stays highlighted; the rest of the manuscript recedes and the toolbar becomes quieter. Writing width and horizontal position can be adjusted independently.

<LightboxImage src="/assets/projects/zentex/zen-mode-20261027.png" alt="ZenTex Zen mode highlighting the active passage and dimming surrounding text" caption="Focus is expressed through the manuscript and the surrounding interface." />

Folding reduces detail without removing the landmarks needed to return. Comments, sections, environments, and the preamble can fold while their boundary commands remain visible. The fold summary uses measured display width, rather than a character count, to fit the available space.

<LightboxImage src="/assets/projects/zentex/folding-20261027.png" alt="ZenTex showing folded section and figure content with structural boundaries retained" caption="Hide the body, keep the structure: folded regions remain identifiable." />

## Treat the project as a connected object

A long manuscript is more than the file currently open. ZenTex builds a project index of headings, labels, bibliography entries, packages, and custom commands. The outline follows included files and reads LaTeX sectioning commands: numbered sections, unnumbered starred headings, and appendices keep their distinct meanings.

<LightboxImage src="/assets/projects/zentex/outline-20261027.png" alt="ZenTex outline spanning multiple thesis files with chapter and section identifiers" caption="The outline connects files through the manuscript’s structure." />

**Leave the next step in the manuscript.** The TODO panel reads both comment notes and todo commands. Checking an item updates the corresponding source to its completed form. Unfinished-only and current-file filters narrow the view without creating a second task system.

<LightboxImage src="/assets/projects/zentex/todo-completed-20261027.png" alt="ZenTex task panel alongside TODO and DONE notes in the source" caption="Tasks stay attached to the text; completing one changes its source note." />

**Bring references into the same flow.** A Zotero library exported as a bibliography file can supply citation candidates beyond the current project. Selecting an external entry adds it to the project bibliography as well as inserting the citation. This is a file-based library workflow, rather than live Zotero synchronisation.

<LightboxImage src="/assets/projects/zentex/zotero-library-settings-20261027.png" alt="ZenTex settings showing Zotero master-library linking, a master bibliography file selector, and the loaded entry count" caption="Link a Zotero library exported through Better BibLaTeX; its entries become available when citing in a project." />

<LightboxImage src="/assets/projects/zentex/completion-20261027.png" alt="ZenTex citation completion offering bibliography entries within the editor" caption="Choose a reference where it is needed; its bibliography entry follows into the project." />

Project search prioritises headings and labels before body-text matches. Commands, environments, references, and file paths have contextual completion, while the symbol panel provides a visual route into less familiar notation.

## Reuse a writing practice

Snippets capture repeatable structures; the Code Palette stores reusable code blocks called **Pigments**. The insertion point follows the command’s role: preamble settings belong before the document body, while writing fragments belong at the cursor. The aim is to make reusable knowledge available without requiring the writer to remember where every command takes effect.

## From a sentence to a typeset page

Compile saves the current text first, so the PDF corresponds to the manuscript on screen. The reader supports source-to-PDF and PDF-to-source navigation through SyncTeX, page modes, thumbnails, zoom, text selection, and optional linked scrolling. The writer can switch between editor-only, split, and output-only views.

<LightboxImage src="/assets/projects/zentex/reader-20261027.png" alt="ZenTex PDF reader alongside the manuscript" caption="The PDF remains the place to check the final page." />

Problems should offer a next step. Diagnostics can be filtered by severity and located in the source. Missing-package names are extracted from the compilation log, including wrapped messages; the recovery action installs into the user’s TeX tree and then recompiles. The application’s bundled files remain separate from that user-managed installation.

<LightboxImage src="/assets/projects/zentex/diagnostics-d44fc011a24d.png" alt="ZenTex showing a compilation issue and its source location" caption="Connect a diagnostic to the passage that needs attention." />

## Make recovery and dependencies explicit

Every save keeps the previous file contents as a snapshot of the original bytes. Version history retains the newest ten snapshots and one per day for the last fourteen days. **Loading a snapshot puts it into the editor; saving is a separate decision.** The writer can inspect it, undo the load, or save the recovered text.

<LightboxImage src="/assets/projects/zentex/history-20261027.png" alt="ZenTex version history listing snapshots with a Load action and recovery explanation" caption="Recovery returns a version to the editor before replacing the saved file." />

Export includes PDF, a project folder or ZIP, Word, and ePub. Word and ePub use a separately installed pandoc dependency. When that dependency is absent, the application explains what is missing. Existing export targets are not silently overwritten.

Local text files remain the document’s source of truth. Settings, saved code, snippets, and snapshots live in inspectable local files; project snippets can override the global collection. Keeping that ownership visible also means acknowledging that a local TeX toolchain and optional export dependencies need setup.

## Seven layers behind one writing experience

A native Swift/AppKit shell hosts the interface in WKWebView, with no Electron or Node runtime required by the application. One process can hold multiple project windows, each with its own session state.

| Layer | Responsibility | Why it matters to the writer |
| --- | --- | --- |
| Native shell | Windows, menus, deep links and notifications | Projects behave as desktop documents. |
| Interface | Project sidebar, writing column, reader and settings | Frequent actions remain within the workspace. |
| Editing core | CodeMirror 6 and source decorations | Readability and direct editing share one text. |
| Project intelligence | Cross-file indexing, outline, tasks and completion | The manuscript remains connected across files. |
| Typesetting | Engines, diagnostics, SyncTeX and export | Writing leads to a checkable page and actionable errors. |
| Local data | Documents, preferences, reusable code and snapshots | The writer retains accessible files and recovery options. |
| Verification | Type checks, automated tests, templates and packaging checks | Changes are checked at several levels of the workflow. |

The supplied 0.17.43 development report records zero type errors, 903 unit tests, 315 backend checks, 1,155 browser end-to-end checks, six compilable templates, and twelve packaging checks. These are a dated development snapshot, not evidence of a user study or an independent test run for this portfolio update.

## Personal toolmaking with AI

My role is to frame the writing problems, shape interactions, and evaluate whether the resulting behaviour serves an actual writing session. Workbuddy and REA support the implementation and investigation. The project combines a reference-driven starting point with decisions drawn from my own manuscript work.

ZenTex remains an evolving personal tool. Its readable preview is not a promise to reproduce every LaTeX package in the editor, and compiled output remains essential. Optional dependencies, local toolchain setup, and the consequences of recovery are part of the experience to explain, rather than hide.

The design goal remains simple: **make more room for writing, with less attention spent managing the workbench.**
